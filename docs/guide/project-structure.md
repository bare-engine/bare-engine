# Project Structure

```
my-game/
├─ src/
│  ├─ game.ts              # entry point, calls StartBare
│  ├─ components/          # your ...Component.ts files
│  └─ generated/assets.ts  # generated, do not edit
├─ public/
│  ├─ data/
│  │  ├─ settingsData.json # prefabs, animations, layers, settings
│  │  └─ levels/           # level files
│  ├─ initial/             # loaded before the game starts
│  ├─ images/              # streamed in when needed
│  ├─ sounds/
│  └─ fonts/
├─ texturePackImages/      # packed into an atlas automatically
├─ package.json
└─ vite.config.cjs
```

**Example:** every sample game uses this layout. The [Platformer](https://github.com/bare-engine/bare-platformer) is a small, complete one.

## `src/game.ts`

The starting point of your code. It calls `StartBare(Game)`, where `Game` extends [`Scene`](./scenes).

## `src/components/`

Your [components](./components). Exported classes extending `Component` are registered with the engine automatically.

## `src/generated/assets.ts`

Generated by the dev server. It gives you typed access to your assets and data, with autocomplete:

```ts
import { Asset, Data } from './generated/assets';

this.AddGameObject(Asset.Image.EMOJI_GEAR);
```

`Asset` holds images, sounds, fonts and levels. `Data` holds prefabs, base prefabs, animations and layers from [`settingsData.json`](./settings-data#generated-names).

::: tip
To make production builds smaller, turn on [`stripGeneratedAssets`](../reference/package-json#stripgeneratedassets). It replaces full paths like `Asset.Image.X` with their values and empties the lists (`Asset.Images`, `Data.Prefabs`, …), and the build tells you about any other use of `Asset` or `Data` it can't replace.
:::

## `public/data/settingsData.json`

Prefabs, base prefabs, animations, layers and game settings. See [settingsData.json](./settings-data).

## `texturePackImages/`

While the dev server runs, images in this folder are packed into an atlas in `public/initial/generated/`. See [Assets](./assets).

## `public/initial/`

Everything here is loaded before your game runs, in parallel with your code.

## `public/images/`

Images here are streamed in when first used. No code changes needed: refer to them by name and the engine loads them.

## `package.json`

Besides your npm scripts and dependencies, this holds engine build settings under `bareEngine`, like your game's `gameId`. See [package.json Options](../reference/package-json).
